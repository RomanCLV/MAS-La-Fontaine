# Module ui (`src/js/ui/`)

| Fichier | Rôle |
|---|---|
| `outils.js` | `Recueil.h(tag, attrs, ...enfants)` (création DOM sans `innerHTML` ⇒ pas d'injection), formats de dates français |
| `app.js` | `Recueil.App` : état (données + état UI), sauvegarde, barre du haut, menu Pages, onglets, rendu |
| `page-semaine.js` | Saisie : colonnes textures/régimes/options = « Toujours affiché » + celles qu'un résident du parc affiché présente (`Modele.colonneAffichee`) ; filtre « Services affichés » (masque des colonnes de la grille, données conservées, au moins un service ; mémorisé dans `App.ui.servicesVisibles`), créer la semaine suivante (reprend les cases de présence à 0 de la dernière semaine, cf. `Modele.semaineSuivante`), supprimer la semaine (confirmation ; impossible s’il n’en reste qu’une ; on bascule sur la voisine), alertes (toujours affichées), bandeau activités, onglets de parcs + champ **« Rechercher un nom (tous parcs) »** (`App.etat.rechercheSemaine`, non mémorisé ; texte non vide ⇒ onglet noir « Recherche « … » (n) » et feuille spéciale : résidents actifs trouvés, sans accents, dans l'ordre des parcs, colonne PARC en plus, saisie des présences identique ; pas de carrés de plats ni de lignes salariés / hors parcs ; cliquer un parc efface la recherche ; le champ garde le focus après chaque re-rendu) (aucun parc → message + bouton « Aller à la page Parcs »), ligne **« Plats <parc> »** sous les en-têtes (un carré par service affiché = colonne du parc sur la feuille cuisine : résidents présents hors partis en activité, plats en plus, salariés du parc ; mis à jour sur place quand on saisit un nombre), puis une ligne par **texture** (carré sur fond de la couleur de la texture, en plats : 1 + une par option « +1 plat » ; seulement les textures qui ont au moins un plat dans le parc sur un service affiché, et aucune si seule la texture par défaut en a (doublon de « Plats <parc> ») ; une ligne qui apparaît ou disparaît après saisie d’un nombre ⇒ re-rendu), puis **« En activité »** si des résidents du parc partent en activité sur un service affiché (plats retirés du parc = `platsPartis`, carré bordé de la couleur de l'activité s'il n'y en a qu'une, info-bulle par activité), grille présences (case présente = nombre de plats via `Calc.poids` : 1 + une par option « +1 plat », ex. 3 avec double plat + gros gourmand ; absente = 0 ; parc sans résident actif → message + « Voir tous les résidents » / « + Ajouter un résident à <parc> », fiche pré-réglée sur ce parc), salariés, Sodexo, Direction, Nettoyage, Nettoyage sans viande, Plats témoins, puis ligne de carrés **« Total hors parcs »** (somme des colonnes Sodexo, Direction, Autres, Témoins de la feuille cuisine ; mise à jour sur place) |
| `page-residents.js` / `page-resident.js` | Bascule Liste / Tableau (mémorisée). Liste type TYPOLOGIE (éditer / archiver / supprimer au survol) ; Tableau : une colonne par texture/régime/option, clic = X, brouillon enregistré d’un coup (cases modifiées entourées) ; fiche (groupes Texture / Régimes et allergies / Options) + absences (une case par service) |
| `page-parcs.js` / `page-regimes.js` | Référentiels (nom, couleur, ordre). Régimes : trois tableaux Textures / Régimes / Options, chacun avec une phrase de description (`TABLES`) ; services concernés et « Toujours affiché » (cases cochables sans « Éditer », info-bulle ; texture par défaut : « — ») ; effet (choix pour les options seulement). La nature (texture / régime / option) ne change plus après création |
| `page-activites.js` | Activités de la semaine (nom, couleur, jour, service, participants ; filtres **« Rechercher un nom »** (sans accents, `Outils.sansAccents`) et **« Cacher les absents »** du créneau — un participant coché reste affiché ; seule la liste est refaite pendant la frappe), presets (charger, mettre à jour, enregistrer ; gardent la couleur). Couleur automatique (`Modele.couleurActiviteLibre`) : une nouvelle activité prend la première des 8 couleurs de `PALETTE_ACTIVITES` qu’aucune autre activité de la semaine n’a (palette épuisée : en boucle) ; un preset chargé garde sa couleur sauf si elle est déjà prise cette semaine. La couleur entoure les cases de la grille Semaine (variable CSS `--act`), la puce et la légende. Un résident = une activité par service : changer de jour/service ou charger un preset retire (avec message) les participants déjà pris ailleurs ; un doublon restant (en rouge) bloque l’enregistrement |
| `page-fichier.js` | Accueil, page Importer, page Exporter (choix de la semaine envoyée → nom du fichier) |
| `page-imprimer.js` | Choix semaine/jours/services/type, aperçu, impression |
| `page-options.js` | Options › « Données en cache » : contenu, origine, dates, place occupée ; « Vider le cache local » (confirmation, avertit si non exporté) → `App.viderCache()` efface `recueil.donnees/meta/ui` et revient à l’accueil |

## Principes
- Onglet = `{type, id?}`, clé `type:id`. Onglets ouverts, actif et « fermés récemment » (pages hors menu seulement : fiches, Imprimer ; voir `fixe()`) mémorisés (`localStorage['recueil.ui']`) et **restaurés** à la réouverture.
- Semaine courante (`App.ui.semaine`, utilisée par Exporter, Imprimer, Activités) : toute activation d'un onglet Semaine la met à jour (`definirActif`, y compris quand la fermeture d'un onglet en affiche un autre). Exporter et Imprimer affichent un choix « Semaine » qui la modifie.
- Chaque page = `Recueil.Pages[type] = { titre(onglet), rendu(onglet) }`. Toute modification passe par `App.modifier(fn)` : applique, sauvegarde, re-rend (option `sansRendu` pour les champs numériques, pour garder le focus).
- Brouillons (fiche résident, tableau des résidents, activité, édition de parc/régime) : en mémoire jusqu'à « Enregistrer ». Chaque page déclare `modifie(onglet)` / `abandonner(onglet)` ; `App.indicateur()` affiche « Modifications non enregistrées » près du titre et `•` sur l'onglet ; confirmation avant de fermer l'onglet, de changer d'élément édité ou de quitter le navigateur. Pendant la frappe : `App.signalerModif()` (sans re-rendu, garde le focus).
- Colonnes textures/régimes/options (grille Semaine, Résidents › Tableau) : groupées par nature (`Modele.groupesRegimes`, ordre du référentiel dans chaque groupe), bandeau « TEXTURES / RÉGIMES / OPTIONS » au-dessus et trait épais entre groupes (`Outils.colonnesGroupees`).
- **Toast** (`App.toast(texte, erreur?)`) : message en bas de l’écran (~3 s, hors de `#app`, masqué à l’impression) après chaque bouton d’enregistrement (fiche, tableau des résidents, parc, texture/régime/option, activité, preset, export) ; si la sauvegarde dans le navigateur a échoué, toast rouge d’erreur à la place.
- **Fenêtres de dialogue** (`App.confirmer(texte, suite, { ok, danger })`, `App.alerte(texte)`) : `<dialog>` de l’appli, jamais `window.confirm/alert` (le navigateur permet de bloquer ces dernières : confirm() répond alors « non » sans rien afficher, et une page ne peut pas détecter ce réglage). Asynchrone : la suite est un rappel ; Échap = Annuler. `App.abandonner(suite, onglet?)` suit le même principe.
- Barre d’onglets : bouton **« + »** à la fin = même menu que « ☰ Pages », ouvert sous le bouton (`App.menuOuvert` = `'pages'` | `'plus'` | `false`).
- Barre du haut : état d’enregistrement, « Modifications non exportées », boutons **Importer** et **Exporter** (toujours visibles).
- Alertes de présence : toujours au-dessus de la grille (bandeau masqué s’il n’y en a aucune, sauf alertes masquées à réafficher). Légende de la grille : « 1 Présent et consommant 1 repas » (vert), « 0 Absent » (rouge uni = 0 saisi à la main, classe `absent`), « 0 Absence planifiée » (rouge hachuré = absence de la fiche, classe `abs-fiche`), activités.
- Présence : presser une case inverse sa valeur ; glisser étend cette même valeur au rectangle entre la première case et la case survolée ; relâcher enregistre (une seule sauvegarde), Échap annule. Clavier : Entrée/Espace inverse une case. Si la nouvelle valeur égale la valeur par défaut (fiche), la saisie est effacée.
- Pas de données au démarrage → écran d'accueil, tuiles (titre + explication) en deux groupes : « Reprendre des données existantes » (« Ouvrir un fichier reçu… » ; place prévue pour un futur import Excel) et « Créer une nouvelle base » (« MAS La Fontaine » = base vide + 7 parcs + preset d'activité Sport jeudi midi, `Modele.baseMasLaFontaine` ; « Base vide »). Page Activités : bouton « Ajouter les presets MAS La Fontaine » tant que Sport manque (par nom). Page Parcs : bouton « Ajouter les parcs MAS La Fontaine (manquants) » tant qu'il en manque un (confirmation, parcs existants inchangés).
- Base vide (accueil, ou Importer › « Repartir de zéro », avec confirmation) : textures/régimes/options = liste par défaut du code (`Modele.REGIMES_DEFAUT`) ; aucun parc, résident, preset ; une semaine = la semaine en cours.
